# Conventions

The rules this library holds itself to, and which of them are enforced
automatically rather than by review.

---

## Enforced by lint

Both rules are verified to fire, not merely configured. A rule that never fires
is worse than no rule.

**No raw hex outside `src/tokens/`.** Covers string literals, template literals
and JSX attributes. The regex is word-boundary anchored so it does not
false-positive on Figma node IDs or `href="#pricing"`.

The one exemption is `*.fixtures.ts`, which holds placeholder imagery for
stories. An SVG data URI cannot reference a CSS custom property. **Do not widen
this to `*.stories.tsx`.** Stories must stay token-only.

**No external margin in `src/components/**`.** Bans `m-*`, `mt-*`, `-mx-*` and
friends. Spacing between components belongs to the parent. Stories are exempt,
since a story legitimately spaces its own demo layout.

Note this fires on internal child margins too. That is not a false positive
worth suppressing: the fix is flex `gap`, which is better layout anyway.

**Gap:** ESLint does not lint CSS, so neither rule covers a `.css` file. The
only stylesheet is the generated token file. If component-level CSS ever
appears, add stylelint.

## Enforced by test

`npm test` mounts every story in headless Chromium and runs axe with
`a11y.test: 'error'`, so a violation fails the run rather than reporting
quietly. 252 tests across 68 files at the time of writing.

Product rules are asserted, not trusted:

| Rule | Where it is checked |
|---|---|
| Approvers never see money | Approval row, mobile approval card, and the whole approver-queue page |
| The week grid never renders a zero | `WeekGridCell`, `WeekGridTotalRow`, and the timesheet page |
| Table columns align | Header vs first row, by comparing their right edges |
| The rate-blind banner cannot be dismissed | Banner, and the approver-queue page |
| Every rail item has an accessible name | `NavRailItem` |

## File conventions

**Shared constants go in `.ts`, never `.tsx`.** The docgen plugin annotates
every exported binding in a `.tsx` file with `displayName` and `__docgenInfo`.
An exported object silently gains two enumerable keys, which corrupts any
`Object.keys()` over it. This produced a component that crashed on every story
while the build stayed green.

**One story file per component, colocated.** `Button/Button.tsx` and
`Button/Button.stories.tsx`.

**`faint-foreground` and `ink-faint` are not text colours.** Both fail AA by a
wide margin — 2.41:1 and 3.58:1. They survive in exactly three places: a
disabled input's value, where WCAG 1.4.3 exempts inactive controls; the
`aria-hidden` breadcrumb slash, which carries no content; and the Foundations
page, which renders the failure on purpose. Anything a user reads uses
`subtle-foreground` or darker.

**A story that must contain a contrast failure marks the node
`data-a11y-exempt`** and excludes that selector via `parameters.a11y.context`.
Never switch the rule off for a whole file — the other 50 swatches on the
Colour page are still checked.

**Optional props that a consumer may clear are typed `?: T | undefined`.**
`exactOptionalPropertyTypes` is on, so `prop?: T` cannot receive an explicit
`undefined`, which stories routinely need to do.

## Story conventions

Every component needs a default, every variant (a matrix is better than
separate stories for review), interactive states, and edge content with the
longest realistic string.

**Copy in stories is real product copy.** Consultancy names, timesheet periods,
invoice numbers. No lorem ipsum, no "Button button button". It is British
English and should stay that way. Placeholder copy hides real layout problems,
which is the entire reason edge-content stories exist.

**Docs text is seeded from the Figma component description.** Those
descriptions carry constraints that are invisible in the pixels, and they are
the reason several components look over-specified.

## Known limits

Worth knowing before you trust a green run.

**Layout assertions in play functions need care.** Anything behind a
`md:hidden` is `display: none` at test width, so its computed padding reads
`0px` regardless of what is declared — that has produced a test that failed for
the wrong reason and could never have passed. Relative comparisons within one
layout pass are sound, and are how column alignment and the Button touch target
are checked.

**Until 2 August 2026 the test run had no CSS at all.** Vitest reads
`vitest.config.ts` *instead of* `vite.config.ts`, so the Tailwind plugin was
never applied to the test project and `@import "tailwindcss"` resolved to
nothing. Stories mounted unstyled and axe's colour-contrast rule measured
browser defaults. Behaviour, ARIA and text assertions were unaffected and
remain valid; **every previous green colour-contrast result was worthless.**
The plugin is now listed explicitly in the test project with a comment saying
why.

**Side-by-side theme stories break landmark components.** Rendering a
`SiteHeader` twice creates two `banner` landmarks and fails `landmark-unique`.
That is a flaw in the comparison, not the component, so those two components
have no side-by-side story. Use the Theme toolbar instead.

**A tab left open across a deploy will fail to load stories, and recovers
itself.** Story chunks are content-hashed, so every build renames them; a tab
holds the shell it loaded and only fetches a story's chunk when you navigate to
it. Once the deployment moves, those filenames are gone. `preview-head.html` and
`manager-head.html` listen for Vite's `vite:preloadError` and reload once, with
a 15 second cooldown so a genuinely missing chunk surfaces the error instead of
looping. If you see "Failed to fetch dynamically imported module" and it does
*not* clear itself, that is a real broken build, not skew.

**Second-order aliases cannot live in `@theme static`.** A token pointing at
another semantic token, rather than at a primitive, gets resolved at build time
and frozen at its light value. `chart-grid`, `chart-axis` and the shadcn
mapping block use `@theme inline`; `--color-focus-ring` is a plain property
declared in both `:root` and `.dark`, because the base layer reads it through
`var()` and `inline` emits no variable.

## Open questions

Design decisions, not defects. All are recorded in `NOTES.md` with measurements.

- **The five new type tokens are code-side only.** `mono/2xs`, `mono/xs`,
  `mono/sm`, `mono/md` and `ui/micro` hold values Figma already specifies on
  component nodes, but Figma has no text styles for them. Promoting them there
  would close the loop; until it does, a designer changing the mono ramp will
  not see these four steps.
- **`SubNavItem`'s count gained `font-mono`** with the token swap, on the
  grounds that every other numeral in the system is mono and its absence looked
  like an oversight. Worth a designer confirming rather than assuming.
